# Zoho Projects-shaped fictional export

`examples/zoho-shaped-portfolio.json` is **synthetic**. It models two project snapshots inside one portfolio so a PM can see a drifted project alongside an aligned project. No Zoho account, trial, token, live API request or customer data is used. Run `PYTHONPATH=src python3 -m milestone_monitor.zoho_sample examples/zoho-shaped-portfolio.json` from the repository root.

The field subset `milestones[].id`, `name`, `owner_name`, `end_date_long`, `status` follows the published Zoho Projects REST [Milestones API example](https://www.zoho.com/projects/help/rest-api/milestones-api.html). `status` is `completed` or `notcompleted`; the latter means **open, with no finer phase known**. We map it to `open_unknown`, not to `planned` or `in_progress`. Thus we cannot detect a planned-vs-in-progress change from this export alone. `last_modified_time` appears in the API's list query parameters; in this fixture it is an **illustrative supplemental field**, not a claim that every milestone response includes it. Its value supplies the timestamp needed for stale-data checks. `baseline` and `as_of` are our **PM-owned snapshot contract**, not Zoho-native fields. The string IDs here are deliberately fictional (rather than claiming a real portal/project ID); production mapping would need to verify the live API version, pagination, permissions and ID formats.

The importer validates epoch milliseconds and translates them to timezone-aware UTC instants. It compares each project independently and reports counts across the portfolio. For the Marigold sample, data-load has stale tracker data and due-date drift, while launch has an owner mismatch. The separate raw `examples/drift.json` demonstrates status drift between two richer *internal* snapshots; that extra phase detail is not claimed to come from the Zoho example. The Indigo sample aligns. A missing project/milestone key, malformed status or unparseable timestamp must not silently disappear.

No review decision or notification is sent by this command. The seven-day staleness threshold is an example PM policy, not a Zoho rule. To use this outside a demo, first resolve exact portal settings, timezone semantics, immutable baseline source, reviewer ownership, and recipient permission.
